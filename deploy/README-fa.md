# راهنمای استقرار سامانه در شبکه محلی اداره

این سند مراحل نصب، اجرا و نگهداری سامانه «مدیریت دارایی و نگهداری فناوری اطلاعات» را
برای اجرا روی یک رایانه یا سرور ویندوزی داخل شبکه اداره توضیح می‌دهد.

---

## ۱) پیش‌نیازها

| مورد | حداقل | توضیح |
|---|---|---|
| سیستم‌عامل | Windows 10/11 یا Windows Server 2016+ | روی همان رایانه‌ای که در شبکه در دسترس است |
| پایتون | 3.12 یا بالاتر | نسخه 3.13 توصیه می‌شود |
| حافظه و دیسک | ۴ گیگابایت رم، ۵ گیگابایت فضای آزاد | برای چند هزار دارایی و عکس‌ها کافی است |
| نرم‌افزار اضافی | ندارد | هیچ وابستگی کامپایل‌شده یا اینترنتی لازم نیست |

> سامانه به اینترنت نیاز ندارد. تمام فایل‌های ظاهری (CSS/JS) و مولد کد QR به‌صورت بومی
> در پروژه قرار دارند.

---

## ۲) نصب گام‌به‌گام

```powershell
# ۱) کپی پروژه روی سرور، مثال:
#    D:\itam

# ۲) نصب بسته‌های پایتون (در صورت نبود اینترنت روی سرور،
#    بسته‌ها را روی رایانه دیگری دانلود و با --no-index نصب کنید)
cd D:\itam
python -m pip install -r requirements.txt

# ۳) اجرای مهاجرت‌های پایگاه داده
python manage.py migrate

# ۴) تنظیمات سازمان (نام اداره و آدرس شبکه) — از داخل خود سامانه هم قابل تغییر است
#    یا از پیش با متغیرهای محیطی:
#    set ITAM_ORG_NAME=اداره کل ...
#    نام کاربری و گذرواژه مدیر ارشد را بسازید:
python manage.py createsuperuser

# ۵) آزمایش سلامت سامانه
python manage.py smoke_test
```

### ساخت داده نمونه (اختیاری، برای آموزش کاربران)

```powershell
python manage.py seed_demo
```

حساب‌های ساخته‌شده با گذرواژه پیش‌فرض `Admin@1403`:

| نقش | نام کاربری |
|---|---|
| کارشناس فناوری اطلاعات مرکز | `admin.it` |
| کارشناس پیمانکار | `tech.pars` |
| مدیر و ناظر | `manager` |
| کاربر / امانت‌دار | `user.karimi` |

> در محیط واقعی، پیش از هر چیز گذرواژه‌ها را تغییر دهید و داده‌های نمونه را حذف کنید
> (`python manage.py flush` سپس `migrate` و `createsuperuser`).

## ۳) اجرای سامانه به‌صورت خودکار (توصیه‌شده)

اسکریپت `deploy\install_service.ps1` را در **PowerShell با دسترسی Administrator** اجرا کنید:

```powershell
cd D:\itam\deploy
.\install_service.ps1
```

این اسکریپت به‌صورت خودکار:

1. مهاجرت‌ها را اعمال و فایل‌های ایستا را جمع‌آوری می‌کند.
2. وظیفه **ITAM-Server** را برای اجرای سامانه در زمان راه‌اندازی ویندوز می‌سازد.
3. وظایف دوره‌ای را ثبت می‌کند:
   - `ITAM-Dispatch` هر ۵ دقیقه — ارسال رخدادها به سامانه مدیریت
   - `ITAM-SLA` هر ۳۰ دقیقه — بررسی و ثبت نقض SLA
   - `ITAM-Visits` روزانه ۰۷:۰۰ — نشان‌دارکردن بازدیدهای خارج از مهلت
   - `ITAM-Backup` روزانه ۲۳:۳۰ — پشتیبان‌گیری خودکار
4. پورت سامانه را در فایروال ویندوز باز می‌کند.

پس از نصب، نشانی دسترسی از داخل شبکه:

```
http://<IP-سرور>:8000/
```

### اجرای دستی برای آزمایش

```powershell
cd D:\itam
.\deploy\run_server.bat
```

اگر بسته `waitress` نصب باشد، از آن استفاده می‌شود؛ در غیر این صورت سرور توسعه جنگو
روی `0.0.0.0:8000` اجرا می‌گردد (برای اداره‌های کوچک کافی است، اما نصب waitress توصیه می‌شود):

```powershell
python -m pip install waitress
```

## ۴) تنظیمات مهم پس از نصب

در سامانه، بخش **تنظیمات سامانه** (فقط کارشناس فناوری اطلاعات مرکز):

| تنظیم | مقدار پیشنهادی |
|---|---|
| نام اداره / سازمان | نام واقعی اداره |
| آدرس پایه سامانه در شبکه | `http://10.0.0.5:8000` (IP سرور) — داخل QR برچسب تجهیزات درج می‌شود |
| مبنای محاسبه SLA | «فقط ساعت کاری اداره» |
| ساعت کاری | ۰۷:۳۰ تا ۱۵:۳۰ |
| روزهای کاری | شنبه تا چهارشنبه (پیش‌فرض) |
| توقف ساعت در انتظار قطعه | فعال |
| تایید کاربر و کارشناس IT | هر دو فعال |

سپس در بخش **تعطیلات رسمی**، تعطیلات سال را ثبت کنید (مناسبت‌های ثابت را با گزینه
«هر سال تکرار می‌شود» وارد کنید). این تعطیلات از ساعت SLA کسر می‌شوند.

## ۵) پشتیبان‌گیری و بازیابی

```powershell
# پشتیبان‌گیری دستی
.\deploy\backup.ps1

# پشتیبان روی درایو دیگر یا شیر شبکه
.\deploy\backup.ps1 -BackupRoot "\\server\backup\itam" -KeepDays 90
```

ساختار پشتیبان: `backups\itam-YYYY-MM-DD_HH-mm\` شامل `db.sqlite3`، پوشه `media`
و کلید امنیتی.

**بازیابی:**

```powershell
# ۱) وظیفه ITAM-Server را متوقف کنید
schtasks /End /TN "ITAM-Server"

# ۲) فایل‌ها را بازگردانید
Copy-Item "backups\itam-2025-01-01_23-30\db.sqlite3" "D:\itam\db.sqlite3" -Force
robocopy "backups\itam-2025-01-01_23-30\media" "D:\itam\media" /E

# ۳) سرویس را دوباره راه‌اندازی کنید
schtasks /Run /TN "ITAM-Server"
```

> نکته: پشتیبان‌گیری از پایگاه داده SQLite در حال اجرا با «SQLite Backup API» انجام
> می‌شود؛ بنابراین نیازی به توقف سامانه نیست.

## ۷) عیب‌یابی

| نشانه | بررسی |
|---|---|
| صفحه باز نمی‌شود | اجرای وظیفه: `schtasks /Query /TN "ITAM-Server"` و فایل `logs\itam.log` |
| خطای «DisallowedHost» | در `deploy\run_server.bat` مقدار `ITAM_ALLOWED_HOSTS=*` تنظیم شده باشد |
| QR به صفحه تجهیز نمی‌رود | «آدرس پایه سامانه» در تنظیمات باید IP واقعی سرور باشد |
| رخدادها ارسال نمی‌شوند | بخش «صف ارسال به مدیریت» → تعریف مقصد و دکمه «ارسال رخدادهای در انتظار» |
| فونت فارسی درست نیست | از مرورگر به‌روز (Edge/Chrome/Firefox) استفاده کنید؛ فونت پیش‌فرض Tahoma است |
| خطای دسترسی به فایل‌ها | پوشه پروژه باید برای کاربر اجرای وظیفه قابل نوشتن باشد (پوشه‌های `media`، `logs`، `backups`) |

بررسی سلامت کامل پس از هر تغییر:

```powershell
python manage.py check
python manage.py test
python manage.py smoke_test
python tools\verify_http.py    # نیازمند سامانه در حال اجرا روی 127.0.0.1:8000
```

## ۸) امنیت در شبکه محلی

- گذرواژه پیش‌فرض `Admin@1403` را تغییر دهید و برای هر کاربر حساب جدا بسازید.
- کلید امنیتی سامانه در فایل `secret_key.txt` نگهداری می‌شود؛ آن را در جای امن پشتیبان بگیرید
  و در اختیار دیگران قرار ندهید.
- در صورت امکان سامانه را پشت یک پروکسی معکوس با گواهی SSL قرار دهید و سپس
  `ITAM_SECURE_COOKIES=1` را فعال کنید.
- دسترسی به پورت سامانه را در فایروال فقط به محدوده شبکه اداره محدود کنید.
- برای کارشناس پیمانکار حساب اختصاصی با نقش «کارشناس پیمانکار» بسازید تا فقط
  تجهیزات قرارداد خودش را ببیند.
