## قواعد سراسری و ممنوعیت‌ها

1. هر تغییر باید مسئله، دامنه، تست رگرسیون، CI، مستندات و ریسک باقیمانده داشته باشد.
2. امنیت و scope باید server-side و fail-closed باشند؛ UI به‌تنهایی کنترل امنیتی نیست.
3. Migration/Seed/Reconciliation apply/Outbox dispatch و هر تغییر DB فقط با بررسی ایمنی و مجوز صریح جداگانه انجام شود.
4. دستورات destructive شامل reset، clean، stash، rebase، force-push و history rewrite ممنوع‌اند.
5. backupها و CSVهای reconciliation حفظ شوند.
6. CI، تست محلی، پذیرش دستی و Production readiness جداگانه گزارش شوند.
7. هیچ قابلیت یا فازی فقط به دلیل وجود کد یا باز بودن PR، تکمیل‌شده محسوب نمی‌شود.
8. هاست و Production تا تصمیم جدید مالک پروژه Deferred باقی می‌مانند.
9. کاربر قبلاً درخواست صریح ادغام PRهای پروژه را داده است؛ این درخواست مجوز عبور از gateهای فنی، نادیده‌گرفتن تعارض یا ادغام شاخه ناقص نیست.
