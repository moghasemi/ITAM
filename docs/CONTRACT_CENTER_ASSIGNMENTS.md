# انتساب پیمانکار رسمی به مرکز

از این نسخه، **قرارداد استانی به‌تنهایی به تکنسین اجازه دسترسی به تمام مراکز استان نمی‌دهد**. هر مرکز باید به‌صورت صریح به یک قرارداد جاری و پیمانکار مربوط منتسب شود.

## قواعد عملیاتی

- برای هر مرکز حداکثر یک انتساب فعال وجود دارد.
- یک قرارداد و پیمانکار می‌توانند به چند مرکز همان استان منتسب شوند.
- یک استان می‌تواند چند قرارداد فعال با پیمانکاران مختلف داشته باشد؛ مراکز هر قرارداد باید جداگانه مشخص شوند.
- پایان انتساب، سابقه را حذف نمی‌کند؛ رکورد با وضعیت پایان‌یافته و دلیل/عامل پایان حفظ می‌شود.
- تکنسین فقط دارایی‌ها، تیکت‌ها، چک‌لیست‌ها و بازدیدهایی را می‌بیند که قرارداد همان رکورد در آن مرکز انتساب فعال دارد.
- جدول قدیمی `Contract.centers` صرفاً داده تاریخی است و مرجع مجوز دسترسی نیست.

## داده‌های قدیمی

Migrationها به‌صورت خودکار از M2M قدیمی یا صرفاً از استان قرارداد، انتساب نمی‌سازند. چنین تبدیلی می‌تواند پیمانکار اشتباه را به مرکز واقعی منتسب کند و دسترسی ناخواسته ایجاد کند.

پس از دریافت نسخه جدید، ابتدا فرمان فقط‌خواندنی زیر را اجرا کنید:

```powershell
python manage.py audit_contract_center_assignments
python manage.py audit_contract_center_assignments --format json
```

این فرمان قراردادهای جاری فاقد انتساب فعال را گزارش می‌کند و تعداد/کد مراکز موجود در M2M قدیمی را فقط به‌عنوان سرنخ نشان می‌دهد. هیچ داده‌ای را تغییر نمی‌دهد.

پس از تطبیق قرارداد و مرکز با مدارک معتبر، مدیر استان از بخش «انتساب پیمانکار به مراکز» انتساب را ثبت می‌کند. برای تغییر پیمانکار یک مرکز، ابتدا انتساب قبلی را با دلیل پایان دهید و سپس انتساب جدید بسازید.

## داده نمونه

فرمان `seed_sistan_demo` انتساب‌های لازم را برای مراکز آزمایشی ایجاد می‌کند؛ یک مرکز نمونه عمداً بدون پیمانکار رسمی باقی می‌ماند تا مسیر رسیدگی توسط کارشناس IT مرکز نیز قابل آزمون باشد.
